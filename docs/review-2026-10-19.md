## 二、P0：建议改

### 1. `13` / `31` 的真实几何是 50/25/25，不是三等分

在 120×40 客户端上实测（`_h_build_layout` 直调，未切焦点）：

```text
13:  p1 0,0  60x40 | p2 60,0  60x20 | p3 60,20 60x10 | p4 60,30 60x10
31:  p1 0,0  60x20 | p2 60,0  60x40 | p3 0,20  60x10 | p4 0,30  60x10
```

`13` 的右列、`31` 的左列都是 **50% / 25% / 25%**，而 README、`hopen.sh` 头部和
`hopen-once.sh` 的 `_h_row_major` 都把它写成 `[A][B/C/D]`，读起来是三个等高的
pane。0.9.1 和 0.9.5 两次 smoke 都记录了 `22/11/11`，但没有把这个数字和文档里的
视觉对齐起来。

两个选择，先定产品意图：

- **A. B 双倍高是有意的**：把文档改成「右 1 大 + 2 小」，`hopen.sh` 头部和 README
  的 `[B/C/D]` 加注，别让用户以为是三等分。
- **B. 要真三等分**：用 0.9.5 的 `--ratio`，只改两条 step，创建顺序不变：

  ```text
  13: ROOT right → LAST down 0.333 → LAST down 0.5
  31: ROOT right → ROOT down 0.333 → LAST down 0.5
  ```

  实测预期 `13 → 13/13/14`。需要动三处：
  1. `scripts/hopen.sh:68` `_h_split` 接受第 3 个参数 `ratio`，有值才传 `--ratio`；
  2. `scripts/hopen.sh:157` 的 `while read` 改成读三列（parent / direction / ratio）；
  3. `scripts/hopen.sh:223` `_steps_for` 改上述两行。

  `_position_for`、`_h_row_major`、三个契约测试都**不用动**，因为创建顺序没变
  （仍是 top → mid → bottom）。`tests/` 里的 fake herdr 会忽略多余的 `--ratio`，
  不会因此挂。

### 2. `--help` 被写死的行号截断

- `scripts/hopen.sh:467`：`sed -n '2,19p'`，但头部注释现在到第 31 行。实际输出停在
  `# Agent 启动：...`，conf 跳过规则和 6 条设计原则全被截掉。
- `scripts/hopen-once.sh:111`：`sed -n '2,71p'`，头部到第 73 行，最后两行
  （`- Kinds placed in row-major visual order`）缺失。

改法：不要维护行号，用「从第 2 行开始连续打印 `#` 行」：

```bash
awk 'NR > 1 && /^#/ { print; next } NR > 1 { exit }' "${BASH_SOURCE[0]:-$0}"
```

这样以后加注释不会再失配。

### 3. 回滚路径的最后一步是必然失败

`scripts/hopen.sh:176-180`：

```bash
for p in "${created[@]:-}"; do herdr pane close "$p" ...; done
herdr workspace close "$ws_id" ...
```

实测（临时 ws `w6M`）：关闭工作区的**最后一个 pane** 会连带销毁 workspace，紧接着
`herdr workspace close` 返回 `workspace_not_found`（exit 1），被 `|| true` 吞掉。
所以不会泄漏，但每次回滚都多一次注定失败的调用，日志上也不好排查。

建议直接 `herdr workspace close "$ws_id"`（实测会连同所有 pane 一起关），或先关
workspace、失败再逐 pane 兜底。同时更正
`docs/herdr-upstream-2026-09-10.md:124-127` 的结论：那里写「确认弹窗可能导致关闭
失败、临时 workspace 泄漏」，**实测 CLI 路径不弹确认**，`ui.confirm_close` 只影响
TUI 手动关闭。

### 4. 版本口径：0.8.2 是契约下限，不是推荐版本

- 0.9.5 #5255 修了中文/日文/韩文输入法下 prefix 快捷键失效；本项目主入口正是
  `prefix+alt+1..9` / `prefix+ctrl+1..9`，文档也是中文。
- 0.9.4 重写了输入管线（#5017），0.9.5 才补齐这个回归。

建议不要直接把 `min_herdr_version` 抬到 0.9.5（会挡住仍在 0.8.x 的用户），而是：

```json
"min_herdr_version": "0.8.2",
"recommended_herdr_version": "0.9.5"
```

`install.sh` 对低于 recommended 的版本打 warning（不 die），并说明 CJK 输入法下
prefix 可能失效。这样既保留兼容性，又给出升级理由。

## 四、P2：工程项

1. **测试套件超过 2 分钟**。`test_hopen_dispatch` 的单个契约测试实测 60.4s，
   `test_hopen_once_dispatch...` 25.5s，全量 `unittest discover` 会被 120s 超时
   SIGKILL。根因是 fake herdr 用 Python 实现，每次 CLI 调用都起一个解释器
   （约 0.15s × 数百次）。把 fake herdr 换成 `/bin/sh` stub，或给慢测试单独
   target，能立刻降到 10s 级。
2. **该切版本了**。`VERSION` 仍是 0.7.0，但 `[Unreleased]` 已有 smoke、契约测试、
   `_read_section_key` 重构等多条；按 `future-directions.md:355` 自己定的「超过 5 条
   就切版本」，可以发 0.8.0。
3. **`install.sh:35` 的 `PREFIX_DEFAULT=cmd+b` 在 Linux 上不成立**。`cmd` 是 macOS
   的修饰键；建议按 `uname` 选 `cmd+b` / `ctrl+b`，或只在 macOS 上 bootstrap。
4. **`agent start -- [AGENT_ARG]` 未透传**（可选）。0.9.5 支持给 agent 传启动参数
   （如 `codex --model`），`hopen.sh` / `hopen-once.sh` 目前没有入口；如果以后要
   在 conf 里配 per-pane 参数，这是唯一需要扩展的地方。

## 五、确认不需要改的（避免过度反应）

- **catalog 不 bump**：24 kinds / 18 targets 与 0.9.5 一致。
- **`startup_per_agent_delay_ms` 与 hopen 无关**：只作用于恢复的 agent，hopen 开的是
  新建 pane。
- **`pane split` 语义变化**：`_h_split` 始终传 target，已由 0.9.5 smoke 复核。
- **`prefix` 数组**：`install.sh` 的 `^\s*prefix\s*=` 能匹配 `prefix = [...]`，不会
  覆盖用户配置。
- **不迁 plugin**：`herdr plugin update`（0.9.4）不构成迁移理由，当前 Recipe Launcher
  边界仍然成立。

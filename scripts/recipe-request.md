# 固定 Recipe 请求

用户给出布局代号（例如 `111`、`22`）并指定各 pane 的 kind 时，执行固定 Recipe。
默认由 `hopen-once.sh` 新建工作区；当前协调者保留，不计入该 Recipe 的 pane 数。
这一路径允许通过启动器创建并核验返回的新工作区，不受 worker 协调的“同 tab”约束。

例如“开始111布局,每个pane 开启pi”已经给足参数，直接执行：

```bash
bash "<scripts目录>/hopen-once.sh" -C "<目标项目目录>" -l 111 -k pi:3
```

脚本目录取本 skill 的项目根下 `scripts/`，或 runtime context 中 `launcher_core` 的
所在目录；目标目录沿用当前任务/runtime cwd。执行前读取该入口的 `--help`，按已有
布局映射确定 pane 数。名称用脚本默认值，未指定初始提示词就留空，启动后等待用户。
布局、kind、目标目录已知时先简短说明默认行为并执行，省去角色、命名、是否保留主
对话和是否需要任务的确认。全局 herdr skill 仅在需要直接操作 pane 时加载。
真实工具权限交给宿主的审批流程；把命令权限提示与布局/角色选择区分开，不通过调整
agent 的全局权限设置来消除提示。

完成条件：核对脚本 exit code、返回的 workspace/pane IDs 和新工作区中的 agent 状态，
再报告成功或具体失败。失败前已创建的资源按脚本诊断保留，不盲目重复创建。

用户明确要求“当前 tab”或“替换现有 pane”时，以该要求为准，不自动另开工作区；
如果会替换正在运行的主对话或影响其它已有 agent，只澄清这一处实际冲突。

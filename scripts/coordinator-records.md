# 本地执行记录

首次准备团队或处理任务时读取。runtime context 的 record_dir 是该团队在目标项目下
`.herdr-recipes/teams/<team_id>/` 的绝对路径。目录不存在时由主协调者创建；已有目录先
读取并核对 team_id，不能覆盖另一个团队。所有 worker 使用同一团队记录位置，不因
跨 tab/worktree 重建团队。主协调者是记录唯一写者，worker 将各自交付写到指定路径。

## team.md

记录 team_id、主 pane/agent、目标目录、启动配置及其来源。在本文件或其明确引用的
本地资源清单中维护资源表，保持一处登记而不重复维护：

| 资源 | 实际 ID/路径 | 角色/kind | 归属来源 | 生命周期/保留要求 | 当前任务 |
|---|---|---|---|---|---|
| workspace/tab/pane/worker/worktree/branch | 查询或创建响应 | 用途与实际 kind | 本团队创建，或用户明确交付 | 存活/已关闭；是否允许回收 | 任务 ID 或待命 |

登记 worker 的 name、pane、tab、workspace 与 checkout 对应关系；启动尝试也预占名额，
只有核对失败/退出后才释放。普通进程单独登记，不计 worker 预算。资源移动或关闭后
更新映射，保留归属与终止记录。已有任务完成后仍存活的 worker 继续占名额。

## tasks/<任务 ID>.md

为每次新任务创建新文件，先查已用 ID，保留旧轮次而不覆盖。最小内容：

```markdown
# <任务 ID> <目标>

## 用户要求与约束
原始要求、有效 worker 类型/数量/上限、本次覆盖、只读/写入等约束。

## 计划与完成标准
子任务 ID、依赖、负责 worker/pane/checkout、允许写入范围、独立交付路径、验收依据。

## 执行与证据
派发结果、worker 本轮回报、实际来源/文件/diff/commit、检查命令和结果。
明确区分计划、派发、worker 自报、协调者已核验、阻塞与未验证。

## 最终交付与待决事项
整合版本/文档位置、联合验证、未完成项及影响、资源保留或回收结果。
```

只保存任务所需事实，凭据与无关终端历史留在原处。该目录是本地协作笔记，不进入
项目提交，也不代替 GitHub Issues。此仓库已忽略 `.herdr-recipes/`；其它项目遵守其
本地忽略约定，定向 stage 时排除记录，不擅自改全局 Git 配置。

记录不是权威运行状态或自动恢复指令。上下文恢复时查询实际资源、Git 和产物，核对
当前任务与基线后才接续；不可核对的任务标阻塞。目录写入失败时报告记录不可用，
不要声称记录或恢复已完成，也不要据未存档结果自动回收 worker。
